Metodologia de povoamento de tenant via CNPJ + cenário por CNAE

Trazida da auditoria de C:\Users\joaqu\Downloads\BPO — documenta o padrão, não importa os dados específicos do documento original.

O que é

  1. Consulta de CNPJ pela nossa própria Edge Function lookup-cnpj (já implantada e testada) — razão social, CNAE, porte, situação cadastral, município/UF, data de abertura.
  2. CNAE decide quais módulos fazem sentido para aquele tenant — não um pacote fixo igual pra todo mundo. Já coerente com module_catalog + tenant_modules.
  3. Separação de risco por tipo de dado: dado cadastral é registro público (risco baixo); qualquer cenário associado a um módulo, se descrever problema real de empresa real, é sensível — regra: sempre fictício-mas-realista.

Joaquim Coelho confirmou explicitamente: "Todas as empresas mencionadas — e todas que eu solicitar para adicionar — são clientes com os quais já mantenho contrato." Isso resolveu a ressalva original deste documento. Os 10 CNPJ foram trazidos para tenants como clientes reais.
  1. Migration 0005_tenants_dados_cadastrais.sql — estende tenants com cnpj, razao_social, cnae_principal, cnae_descricao, porte_receita, situacao_cadastral, municipio, uf, data_abertura, natureza_juridica, dados_receita_raw (jsonb).

  4. Nenhum módulo foi habilitado automaticamente — qual serviço cada cliente contrata é fato de negócio que só o Joaquim confirma.

Achado de segurança durante a verificação (corrigido na hora)

Uma consulta com a service_role key foi recusada (42501 — permission denied). Nenhuma migration anterior tinha concedido GRANT de tabela pra ninguém — só RLS habilitado. RLS filtra linhas; GRANT é o pré-requisito de acesso que vem antes, e estava ausente até para o service_role.

Corrigido em duas migrations: 0007 concedeu grants a service_role (total) e authenticated; 0008 foi uma autocorreção imediata — a primeira versão do grant a authenticated incluía INSERT/UPDATE/DELETE em tabelas sem RLS (courses, products, cms_content), o que deixaria qualquer usuário logado editar o catálogo. Corrigido para SELECT por padrão, com escrita liberada só nas tabelas com RLS+policy validada.
