1. Parecer executivo

É tecnicamente viável evoluir o legado para um ERP web multiempresa, mas a migração não deve começar por importação direta. As telas comprovam funções, porém não revelam tabelas físicas, chaves, relacionamentos, triggers, procedures, versão original ou volumes. Esses nomes somente serão preenchidos depois de uma restauração isolada e validada.

O acervo contém 68 arquivos e 5.495.739 bytes: 64 PNG, dois DOCX e dois TXT. Não existe arquivo .bak, .mdf, .ldf, arquivo compactado ou outro banco conhecido no staging. Nenhuma restauração foi tentada. O próximo ato seguro é receber uma cópia representativa, registrar custódia e validar a mídia antes do restore.

2. Escopo e limites

Executado

  • Inventário somente leitura.
  • Extração textual dos dois documentos Word.
  • Classificação funcional das 38 telas legadas.
  • Comparação conceitual com o Supabase atual.
  • Inspeção somente leitura das ferramentas locais.
  • Matriz preliminar e desenho do laboratório/rollback.

Não executado

  • Restore, criação ou alteração de banco.
  • Migration, carga de cliente ou código ERP.
  • Alteração de produção, Vercel Production ou Mercado Pago.
  • Movimentação de senhas, A1 ou dados pessoais para Git.
  • Instalação/reconfiguração de SQL Server ou Docker.

4. Domínios do legado

Cadastros; produtos/código de barras; estoque/compras; preços/orçamentos; vendas/PDV; cartões/TEF; receber/pagar/caixa/cheques/boletos; atendimento; NF-e/NFC-e/A1; relatórios/logs/backup/importação/exportação e suporte.

A1 é credencial fiscal, não login. Senhas antigas não serão migradas; a nova identidade usará Supabase Auth, MFA, convite e menor privilégio.

5. Divergências de cadastro

  • Word: 14 empresas; configuração do site: 15 posições; migration histórica: 10 tenants.
  • Staging tem apenas um tenant ativo, a ConnectionCyber, sem CNPJ/domínio de cliente.
  • Há e-mails administrativos repetidos entre empresas.

Provisionamento automático permanece proibido até existir cadastro mestre validado.

6. Modelo de destino

O Supabase atual tem tenancy e autenticação, mas não um ERP canônico. products, orders, order_items e payments pertencem ao site/Mercado Pago e não devem receber o legado. Dezesseis de 39 tabelas públicas observadas estão sem RLS. O M02 deverá criar tabelas erp_* com tenant_id, RLS, auditoria e mapa de IDs.

8. Candidato e laboratório

Maria dos Remédios/Mania de Moda é a candidata provisória, pois suas telas demonstram maior cobertura. A escolha só se torna definitiva após receber metadados da cópia.

O SQLEXPRESS atual não deve ser usado. Preferência: container SQL Server 2022 Developer dedicado, volume exclusivo, sem porta pública e backup somente leitura. Alternativa: instância Windows Developer dedicada CCLAB. Nunca executar WITH REPLACE.

Se outro cliente for escolhido, substituir o nome. Não enviar a única cópia original, senha A1 ou credenciais em mensagem.
