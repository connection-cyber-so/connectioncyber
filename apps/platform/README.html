Fase 1 concluída (esqueleto + login). 4 módulos de negócio em produção: Diagnóstico Digital (IA), Catálogo de Produtos e Ofertas (IA), Roteiro de Vídeo (IA) e Landing Pages, todos migrados de cc-commerce-studio — ver docs/migracao-diagnostico-digital-cc-commerce-studio. Layout compartilhado (2026-08-15): topbar + menu lateral + rodapé viraram um único layout.tsx — navegar entre módulos não perde mais o menu. Nome corrigido para ConnectionCyber (era "ConnectionCyberSO"), com a identidade visual oficial: "Connection" em vermelho (#E01F27), "Cyber" em verde (#2C9C48).

Painel interno de gestão de tenants, módulos e clientes — separado do site institucional (apps/site). Só a equipe entra aqui; clientes finais usam apps/site (/membros).

Decisão de arquitetura

Next.js 14 + App Router, diferente do apps/site (Pages Router). Decidido com Joaquim Coelho em 2026-08-15: Server Components consultam o Supabase direto no servidor — sem API route intermediária a esquecer de proteger — alinhado ao modelo de isolamento por tenant já adotado, e ao padrão já usado no resto do ecossistema auditado (bpo-system-web-os, food-service-os, cyber-varejo-os). apps/site continua Pages Router — não há necessidade técnica de convergência.

Modelo de segurança

O servidor deriva o usuário da sessão via cookies (@supabase/ssr), nunca de dado enviado pelo cliente. middleware.ts usa supabase.auth.getUser() (não getSession()) — valida o JWT contra o servidor do Supabase a cada request.
