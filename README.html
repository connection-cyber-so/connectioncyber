Decisões de arquitetura confirmadas

  • Multi-tenant: 1 projeto Supabase único (qfggetvashdxyuvlhihq), isolamento por tenant_id + RLS. Cliente novo = linha em tenants, não projeto/repositório/pasta novos.
  • Staging: clone irmão do repositório, não aninhado (F:\Projetos\connectioncyber-staging).
  • Site: parte deste monorepo (apps/site), não projeto separado.
  • Stack por app: apps/site é Pages Router (sem dado sensível de tenant); apps/platform é App Router (decidido em 2026-08-15) — Server Components consultam o Supabase direto no servidor, alinhado ao padrão do resto do ecossistema auditado. Os dois apps não precisam convergir.
