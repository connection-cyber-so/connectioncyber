PARECER

O que eu faria se fosse meu projeto

Modelo C “+”: um catálogo de cursos que existe 1 vez só (na ConnectionCyber), onde cada curso carrega etiquetas de alvo (qual sistema / qual segmento / público geral), combinado com ativação automática por regra — o sistema lê que sistema aquele cliente usa e libera sozinho o treinamento dele — mantendo matrícula e progresso por pessoa, isolados por cliente (RLS). Não repito curso por cliente (peso), não deixo cada cliente inventar o próprio (dispersão), e o aluno cai direto na trilha do sistema dele. É o mesmo padrão que grandes LMS usam: conteúdo central + entrega contextual.

O detalhe decisivo: você já tem no banco tudo que identifica “de que sistema o cliente faz parte” — tenants.vertical (nicho) e tenant_modules.module_key (módulos/sistemas ativos). Só falta ligar isso ao curso.

Cada camada tem uma responsabilidade. Nenhuma repete curso.

CAMADA 1 — CONTEÚDO (1x só, na ConnectionCyber) Curso existe uma vez no catálogo global. Carrega: título, módulos, duração, preço e etiquetas de alvo.
Hoje a tabela tem tenant_id NOT NULL (curso preso a1 cliente) → é isso que muda.

publico — geral para todo mundo
CAMADA 3 — VÍNCULO (quem recebe)Regra automática: cliente tem o sistema X → recebe os cursos de X.

Tabela nova academy_tenant_courses
CAMADA 4 — ACESSO (inalterado)login → membership ativa → chave academy.courses ligada → matrícula → progresso da pessoa.

INTERFACE — “Treinamento” no portal do cliente Aluno abre Treinamento → o servidor já sabe qual é o sistema daquela empresa → mostra a trilha certa (curso do sistema dele + cursos gerais). Sem ele procurar.

Qual sistema/segmento esta empresa usa? (tenant_modules + vertical)
Busca no catálogo: cursos daquele sistema + cursos gerais + cursos criados só por ela

NÃO → fica só no catálogo, sem histórico

6. Riscos e decisões que dependem de você ANTES DE CODAR

  • Venda de cursos ao público (B2C): se o portal for também loja, o catálogo global vira a base da compra → é a Camada 1 que sustenta. Vale decidir já (afeta preço, carrinho, nota fiscal).
  • “Dentro do aplicativo do cliente”: não precisa de app novo — o portal já abre por endereço da empresa. Se um dia o ERP de cada cliente quiser embutir, ele só aponta para a rota /treinamento daquela empresa (deep-link).
  • Dado de cliente: continua isolado por RLS — curso é global, matrícula e progresso nunca são.
  • Migração do que já existe: os 3 cursos semeados hoje (Atalhos de Teclado em Casa de Bolos, Loja da Benção e Mania de Modas) viram 1 curso global com 3 vínculos.
  • Sequência sugerida (portões): M23-G2 = catálogo global + vínculo (migration + curadoria); M23-G3 = regra automática por sistema + botão Treinamento; depois disso, M24 = venda/preço se você quiser.
